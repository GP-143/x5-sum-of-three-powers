# COVERAGE AND METHOD  (searched for the 635 n not excluded by the congruence; for the 364 excluded n the proof above already settles it)
#   Two search programs, run independently over all |x|,|y|,|z| <= 10^7 for n = 1..999:
#     Search program 1 (solve.cpp): modular fifth roots + exact discriminant tests, pruned by sign/size structure; all 635 n in one
#       run, 35 slices of the s = |x+y| sweep, 7.484*10^9 (s,z) candidates, about 37 minutes on one core.
#     Search program 2 (fifth3.cpp): lattice method, boxes along the cone x^5+y^5 = z^5 with LLL + Fincke-Pohst in each box, plus a
#       direct scan of |a|,|b| <= 500; one run per n (--zmin 500), 567 s in total on one core, all 635 runs ended with 0 box failures.
#   The two programs return identical solution sets for all 635 n, and for n <= 300 exactly the earlier n = 1..300 list.
#   Independent exhaustive scan (slab_scan.cpp, no pruning, shares no code) of the boundary slab max|variable| = 10^7
#   for all n = 1..999, the excluded n included: it found only the family members (-10^7, 1, 10^7) for n=1, (-10^7, 2, 10^7) for n=32,
#   (-10^7, 3, 10^7) for n=243.  (That scan was itself checked against brute force on every boundary R = 1..200.)
#   Every listed solution was re-checked with exact big-integer arithmetic.  Both search programs were cross-checked against brute
#   force (sorted fifth-power table + binary search) for all 635 n up to R=20000; program 1 also against its own --selftest and --test
#   (its fast root finders against the general routine for n = 301..999 as well), program 2's box enumeration against an independent
#   brute force on near-cone points.  Completeness in the box rests on that validation and on the pruning lemmas of the two programs;
#   it is a computation, not a formal proof.  (As the congruence predicts, the brute-force scans, which include the excluded n,
